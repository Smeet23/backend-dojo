## The goal

The aim is simple: to be able to build backends that **grow from zero users to a million** and that **other people can maintain for years**. Frameworks, languages and libraries hide a lot from you every day. This course is about understanding what they hide.

## Three phases

| Phase | Focus | What you get |
|---|---|---|
| **1. Principles** | The ideas and patterns behind every backend, and how they connect | A language-agnostic mental model (this course) |
| **2. Implementation** | Each principle in a specific language and ecosystem | Real code, e.g. Postgres with a Node driver vs Go's `pgx` |
| **3. Production projects** | Everything combined in end-to-end builds | Industry-standard projects you could ship |

## Why this order works

Code makes much more sense once you know **what problem it's solving**. If you already understand connection pooling, migrations and transactions, a database library's docs read like a checklist, not a mystery.

<Callout kind="tip">
In Grokstack, phases 2 and 3 are the **module projects** and the **capstone**: you build things yourself after each group of lessons.
</Callout>

## What "first principles" means here

It doesn't mean memorising rules. It means recognising the **universal building blocks**: routing, validation, auth, data access, error handling and so on. You'll find these blocks in every backend, whatever language or framework it's written in.
